# Aloha-L BOM 콘솔

S040 · S041 · S042 전장 BOM을 **① 설계 Master(기준)** → **② SAP** → **③ 구매** 순서로 비교하고,
차이를 구역 담당 엔지니어(ER / Accommodation / On-deck)에게 보낼 엑셀 리포트로 만드는 Windows 프로그램입니다.

## 쓰는 법
1. `AlohaBOM.exe` 실행. 처음에는 예시 데이터로 화면이 열립니다.
2. **설정 > 파일 폴더**에서 설계 Master / SAP / 구매 파일이 들어오는 폴더를 지정합니다. 각 폴더의 가장 최근 파일을 비교합니다.
3. **설정 > 구역 규칙**에서 블록이 어느 구역인지 정합니다. 오른쪽 미리보기에 미지정 블록이 없어야 합니다.
4. 열을 못 찾는다는 경고가 나오면 **설정 > 열 이름**에서 그 파일의 머리글을 별칭에 추가합니다.
5. **엔지니어 리포트**: 한 파일(구역별 시트) 또는 구역별 파일로 저장. 리포트 직전에 폴더를 다시 확인합니다.

## 화면
- 대시보드: 호선별 설계 → SAP → 구매 흐름, 구역별 follow-up 건수, 일별 deviation 추이, 지난 리포트 이후 해결 현황
- 목록: 단계·종류·호선·구역·블록·검색으로 좁히기 (블록은 차이 많은 순)
- 상세: 세 파일 값을 나란히, 설계 기준과 다른 칸은 빨간색 + SAP팀/구매팀 요청 문장

## 자동 감시 · 이력
- 켜져 있는 동안 세 폴더를 설정한 간격(기본 5분)으로 확인하고, 새 파일이 오면 바로 재비교합니다.
- 비교할 때마다 이력(SQLite)에 기록합니다. 팀이 같은 이력을 보려면 설정에서 N: 공용 폴더로 지정하세요.
- **설정 > 저장 위치 > 매일 아침 7시 자동 기록 등록**: 프로그램을 안 켠 날도 `AlohaBOM.exe --scan`으로 기록.

## 업데이트 배포
새 `AlohaBOM.exe`와 `version.json`을 설정의 **업데이트 폴더**(예: N: 공용 폴더)에 올리면,
각자 exe를 켤 때 버전을 비교해서 스스로 교체하고 다시 켜집니다.

## 개발
```
pip install -r requirements-dev.txt
python -m pytest -q tests
python -m bom_console          # 실행
build.bat                      # Windows에서 exe 만들기 → dist\AlohaBOM.exe
```
GitHub에 push하면 Actions가 Windows exe를 만들어 아티팩트로 올립니다. `v0.2.0` 같은 태그를 push하면 Release에 exe와 version.json이 붙습니다.
